# Практикум по трансформерным нейронным сетям

Электронное приложение к учебному пособию «Матричное исчисление, оптимизация и спектральный анализ латентных представлений трансформерных нейронных сетей».

Авторы пособия: П. А. Пылов ([PylovPetr](https://github.com/PylovPetr)), Р. В. Майтак ([MaytakRoman](https://github.com/MaytakRoman)), А. В. Протодьяконов.
Указание авторов пособия не означает наличие у них учётных записей, прав доступа или истории коммитов в этом репозитории.

Версия комплекта 1.0.0. Комплект создан по спецификации глав 7–8 и приложения Г рукописи; это новая реализация описанного генератора, а не извлечение ранее приложенного архива.

## Запуск генератора

Проверенное окружение: Python 3.12.14, NumPy 2.3.5, CPU, Linux.

```sh
python -m venv .venv
```

Активируйте окружение: macOS/Linux — `source .venv/bin/activate`; Windows — `.venv\Scripts\activate` в cmd.

```sh
python -m pip install -r requirements.txt
python smoke_test.py
python transformer_labkit.py --lab 1 --variant 17
python transformer_labkit.py --verify runs/lab1_variant17
python -m unittest discover -s tests -v
```

На macOS/Linux команда интерпретатора может называться `python3`. Номер работы: 1–4, вариант: 1–60. Все данные создаются локально; внешние корпуса, API и GPU не нужны. `--n 64` задаёт число train-объектов (valid/test: max(2,n//4)); в работах 3–4 — число контрольных объектов. `--out PATH` задаёт новый каталог результата. Существующий каталог не перезаписывается: выберите другой путь.

Для студенческой реализации модели второй работы и построения графиков установите дополнительное окружение:

```sh
python -m pip install -r requirements-teaching.txt
```

PyTorch отсутствовал в среде сборки: его фрагменты проверены синтаксически, интеграционный тест отмечен как пропущенный. Они требуют отдельного запуска после установки PyTorch. Файл `requirements-teaching.txt` задаёт минимальные версии из пособия, а не проверенное фиксированное окружение; фактические версии сохраняйте в отчёте. На Windows/macOS запуск не проверялся.

## Состав и граница задания

| Компонент | Назначение |
|---|---|
| `transformer_labkit.py` | Генерация 4 × 60 заданий, JSONL/NPZ, адресные потоки, manifest и проверка |
| `scaffolds/` | Четыре каркаса с TODO; решения студент реализует самостоятельно |
| `listings/` | Читаемые примеры шести фрагментов главы 7 в двух модулях |
| `tests/` | Контроль всех 240 сочетаний, семантические и отрицательные проверки |
| `examples/` | По одному сохранённому примеру для каждой работы, вариант 17 |
| `variants.csv` | Таблица всех 60 вариантов из приложения Г |
| `ASSIGNMENTS.md` | Действия и артефакты четырёх работ |
| `REPORT_TEMPLATE.md` | Шаблон отчёта |
| `FORMAT.md` | Форматы, правила задач и происхождение данных |
| `verification_report.json` | Фактический отчёт проверки комплекта |

| `SHA256.json` | Контрольные суммы файлов комплекта, кроме самого манифеста |

Каркасы намеренно завершаются `NotImplementedError`, пока не выполнены TODO. Прохождение тестов генератора не означает выполнения лабораторной работы. Эталонная модель трансформера и полные алгоритмы CKA, PCA, обучения и приёмки не поставляются: это задания пособия.

В исходном DOCX строки программ главы 7 слиты. В `listings/` восстановлены переносы и отступы, добавлены импорты, параметры функций и диагностический пример. Контрольная точка дополнена состояниями Python/CUDA и полем состояния sampler; восстановление и согласование пользовательских RNG/worker студент реализует отдельно. Это адаптированные примеры, а не побайтная копия листингов.

## Происхождение контрольных данных

Работы 1–2 получают синтетические последовательности шести семейств. Табличный Seed равен `1000 + 7919 * variant`; рабочие потоки адресуются SHA-256 по формуле 8.1 с явным разделителем `|`, роль включает split, номер объекта и тип случайности. Табличный seed сохраняется для связи с приложением Г и не подменяет независимые потоки.

Работа 3 получает **искусственные контрольные представления**, а не активации обученной сети. Для основного исследования нужны парные активации и ID собственной модели из работы 2. Контрольный набор позволяет проверить вращение базиса, нарушение парности и анализ размерностей.

Работа 4 получает **искусственные прогнозы и условные ресурсные числа**, а не измерения GPU/CPU. Прогнозы stress/ablation являются контролями над оценками; они не доказывают эффект вмешательства в обученный трансформер. Для содержательного ресурсного эксперимента студент измеряет время и память собственной модели.

## Воспроизводимость

`manifest.json` содержит версию схемы и генератора, параметры, хеш генератора, версии Python/NumPy, байтовые хеши файлов и логические хеши массивов NPZ. JSON сериализуется в UTF-8 с сортировкой ключей и разделителями без пробелов, строки завершаются LF. Метаданные ZIP/NPZ могут менять байты контейнера; равенство массивов проверяется по dtype, форме и C-порядку значений. Исходные поля `latent` и checksum нужны для проверки генератора; подавать их модели как признаки нельзя.

Результаты тестов находятся в `verification_report.json`. Проверка 240 заданий использует малые размеры выборок и подтверждает контракт генератора, но не качество обучения и не полную корректность студенческих решений.
