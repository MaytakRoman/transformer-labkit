# Задания и результаты

## Работа 1

Создайте вариант с `--lab 1`. Реализуйте `scaffolds/lab1_attention.py`.
`attention_inputs.npz` содержит Q/K/V формы [heads, tokens, head_dim] и допустимую маску [tokens,tokens]. Температура берётся из config.json; softmax применяется по ключам.
Сохраните таблицу ручного примера, ошибки относительно эталона, суммы строк, массу на запрещённых позициях и отрицательный контроль. Проверка причинности применима только к causal, для window проверяется локальная область доступа, для bidirectional — отсутствие причинного ограничения.

## Работа 2

Создайте вариант с `--lab 2`. Реализуйте `scaffolds/lab2_train.py` в PyTorch.
Используйте input_ids и attention_mask как вход; target_ids/loss_mask — для потери. Поле latent модели недоступно.
Разделяйте обучающий, валидационный и тестовый наборы. Решения выбирайте по valid, итоговые метрики считайте по test после фиксации конфигурации. Сохраните веса, состояния оптимизатора/расписания/RNG, config, кривые потерь, прогнозы с ID и активации для третьей работы.
Проверьте переобучение малого набора, восстановление обучения, корректность градиента и масок. Генератор не выполняет обучение за студента.

## Работа 3

Создайте вариант с `--lab 3`. Сначала проверьте алгоритмы `scaffolds/lab3_representations.py` на control_representations.npz.
Синтетический Y получен ортогональным преобразованием X с малым шумом; y_unpaired нарушает порядок объектов. У обоих матриц одинаковые формы; для содержательной меры нужно соблюдать соответствие строк. Отрицательная перестановка должна диагностироваться, а не объявляться вторым парным запуском.
Затем повторите анализ с активациями модели работы 2 и сохранёнными ID. PCA обучается на train; метки не используются для подбора кластеризации по тесту. Сохраните CKA, ошибку ортогонального согласования, спектр, объяснённую дисперсию и условия анализа.

## Работа 4

Создайте вариант с `--lab 4`. Реализуйте `scaffolds/lab4_evaluation.py`.
predictions.jsonl содержит парные valid/test-объекты и три искусственных кандидата. Порог и температуру выбирайте на valid; решение замораживайте до test. Постройте матрицы ошибок, BACC/MCC/F1, Brier и ECE с объявленными границами интервалов, затем карту допуска по всем обязательным ограничениям config.json.
В resources.json значения помечены как simulated_not_measured. Они подходят для проверки логики ограничений. Измерения реального времени и памяти собственной модели выполняются отдельно с разогревом и повторами.
Сравните основной, стрессовый, абляционный и разрушающий контроль. Эти синтетические прогнозы не свидетельствуют о причинном влиянии компонентов модели. Если нет допустимых кандидатов, результат — отказ с причинами.
